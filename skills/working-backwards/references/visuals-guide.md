# Visual brief guide

Visuals create a shared model of the proposed customer experience. They are part of the thinking, not decoration.

## Start with the main scenario

Choose the single scenario that best shows the customer moving from their current problem to the proposed result. State the customer, starting context, main task, important decision, and end state.

## Match format to the question

- **Flow:** steps, decisions, and failure paths.
- **Storyboard:** customer context and moments over time.
- **Experience map:** stages, touchpoints, needs, and friction.
- **Wireframe:** information, controls, and interaction in one screen or page.
- **System sketch:** actors, inputs, outputs, and dependencies.

Use the simplest format that answers the open question.

## Match fidelity to maturity

Start low fidelity while the customer, problem, scope, or flow remains disputed. Detailed visual polish can pull review toward appearance before the experience is settled. Increase fidelity only when the decision requires it.

## Visual brief fields

- Most important scenario.
- Customer and starting context.
- Proposed steps and result.
- Main risk or open decision to show.
- Chosen format and why.
- Detail intentionally omitted.
- Evidence or user input needed before higher fidelity.

This skill writes the brief. It does not draw, generate, or publish the visual.
